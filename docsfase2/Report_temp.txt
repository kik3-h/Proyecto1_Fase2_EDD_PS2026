1. INTRODUCCIÓN
En el presente documento describe el diseño, implementación y análisis de rendimiento de un sistema
de gestión de catálogo de productos para supermercado. El proyecto fue desarrollado en C++17
utilizando programación orientada a objetos e implementando desde cero las siguientes estructuras de
datos:
- Lista Enlazada (no ordenada)
- Lista Enlazada Ordenada (por nombre)
- Árbol AVL (indexado por nombre)
- Árbol B (indexado por fecha de caducidad)
- Árbol B+ (indexado por categoría)
El objetivo principal es demostrar empíricamente las diferencias de rendimiento entre búsquedas
secuenciales O(n) y búsquedas logarítmicas O(log n), justificando teóricamente las complejidades
algorítmicas de cada estructura.

3. Justificación Detallada: AVL vs Lista Enlazada
Árbol AVL - O(log n): El Árbol AVL garantiza una altura máxima de aproximadamente 1.44 * log₂(n) debido a
su propiedad de balanceo. En cada nivel del árbol, se toma una decisión binaria (ir a la izquierda o derecha), lo
que reduce el espacio de búsqueda a la mitad en cada paso. Para un catálogo de 1000 productos, esto significa
aproximadamente 10 comparaciones en lugar de 1000.
Lista Enlazada - O(n): La lista enlazada no proporciona ningún mecanismo de acceso directo o indexación.
Para encontrar un elemento específico, se debe comenzar desde la cabeza y visitar cada nodo secuencialmente
hasta encontrar una coincidencia o agotar todos los elementos. En un catálogo de 1000 productos, el caso
promedio requiere 500 comparaciones y el peor caso requiere 1000.

4. METODOLOGÍA DE MEDICIÓN
4.1 Configuración del Experimento
La medición de rendimiento se realizó siguiendo la metodología especificada en el enunciado del proyecto:
-

N = 20: Cantidad de consultas consecutivas por prueba

-

M = 5: Cantidad de repeticiones del experimento

-

Tiempo final = (Suma de M mediciones) / M

4.2 Implementación Técnica
Se utilizó la biblioteca <chrono> de C++17 para mediciones de alta precisión:
auto inicio = std::chrono::high_resolution_clock::now();
// Ejecutar N búsquedas consecutivas
for (int i = 0; i < N; ++i) {
volatile Producto* resultado = estructura.buscar(terminos[i]);
(void)resultado;
}
auto fin = std::chrono::high_resolution_clock::now();
std::chrono::duration<double, std::milli> duracion = fin - inicio;
tiempoMs = duracion.count();

Notas importantes:
-

Se utilizó volatile para prevenir optimizaciones del compilador que podrían eliminar las búsquedas

-

Los tiempos se midieron en milisegundos con precisión de tipo double

-

Se probaron tanto búsquedas exitosas (elementos existentes) como fallidas (elementos inexistentes)

6. CONCLUSIONES
Conclusión 1: Superioridad del Árbol AVL para Búsquedas
Los resultados empíricos confirman la superioridad teórica del Árbol AVL sobre las estructuras lineales. Con un
speedup de aproximadamente 50x para búsquedas exitosas, el AVL demuestra ser la estructura óptima cuando se
requieren búsquedas frecuentes por un criterio específico (en este caso, el nombre del producto). Esta diferencia
se vuelve más pronunciada a medida que aumenta el tamaño del catálogo.

Conclusión 2: Importancia de la Elección de Estructura según el Caso de Uso
Cada estructura implementada tiene su propósito específico:
-

Árbol AVL: Ideal para búsquedas exactas por nombre con O(log n)

-

Árbol B: Óptimo para consultas por rango de fechas

-

Árbol B+: Eficiente para recorrer todos los productos de una categoría gracias a las hojas enlazadas

La selección de la estructura correcta según el tipo de consulta es fundamental para el rendimiento del sistema.

Conclusión 3: Validación de Complejidades Teóricas
Las mediciones empíricas validan las complejidades teóricas Big-O analizadas. La relación entre los tiempos de
Lista O(n) y AVL O(log n) es consistente con lo esperado matemáticamente. Para n=1000, log₂(1000) ≈ 10, lo
que implica una diferencia teórica de 100x entre O(n) y O(log n), valor cercano al speedup observado de 50-97x
considerando constantes de implementación.
